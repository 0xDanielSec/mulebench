# Detection evaluation 02: monitor rules over pilots 01-11

**Status: offline evaluation, not pre-registered, design-informed.** No model
was called, no trial was re-run, and no frozen pilot document or data file was
changed. Every rule evaluated here is hand-written, and every pilot evaluated
here informed the design of some of the rules. The numbers describe how the
rules fit the data they were designed on. They are **not** an out-of-sample
estimate. The only true out-of-sample test for these rules is the phase-2
confirmatory pilot: new, frozen scenarios run on fresh seeds after the rules
are fixed.

Previous evaluation: [monitor-eval-01.md](monitor-eval-01.md) (pilots 02-03,
one model). Method and tooling: [../monitor.md](../monitor.md), sections "Rule
provenance", "Detection evaluation" and "Tell lint".

## Read this first

1. **Two kinds of rules, two kinds of numbers.** The monitor runs the same
   invariant and disclosure code the harness uses to label trials, and
   `attack_success` for read scenarios depends on disclosure attribution.
   - **Label-coupled rules** (INV-1..4, `MB-DISC-*`) therefore agree with the
     label almost by construction. Their recall is an **agreement check**
     between monitor and harness. It is not a measure of detection ability,
     and this document never uses it as one.
   - **Independent heuristic rules** (the MEMORY write and context rules, the
     lexical delegation rules, and every other rule whose logic is not the
     labelling code) are the **detection result**. The headline is theirs.
2. **Design-informed, not held-out.** The rules of 2026-11-13 were designed
   after pilots 01-03. The three automatic-memory rules
   (`MB-MEM-instruction_write`, `MB-MEM-foreign_reference_write`,
   `MB-MEM-action_from_context`) were designed on 2026-11-22 after pilots
   01-11, and `MB-MEM-action_from_context` was narrowed after a false positive
   on pilot 11. Each rule document records its design date and the pilots it
   saw (`mulebench.provenance`). The LOPO, LOMO and LOSO folds below are
   therefore labelled **design-informed held-out**: the held-out fold already
   informed the rules. Plain "held-out" is reserved for rules derived by a
   procedure that never saw the fold, and there are none yet.
3. **One scenario dominates.** 77% of the positives are
   `memory-auto-persistent-exfiltration-014a`. Pooled recall is mostly a 014a
   number. Read the macro recall (scenarios weighted equally), the recall
   excluding 014a, and the `narrow: 014a-specific` flags.
4. **Lab scenarios, shared vocabulary.** The scenarios and the detector come
   from the same project. A lint (`mulebench detect lint`) keeps canaries,
   synthetic ids, scenario domains, payload text and scenario amounts out of
   every rule, but a rule can still fit a scenario structurally.

## Method

- **Input:** every report in `docs/experiments/data/` that stores scenarios
  (23 reports, pilots 01-11; the two workload reports are skipped).
- **Replay:** each trial is adapted to a monitor trace
  (`mulebench monitor adapt`). That includes the new `memory_write` events
  from the stored extractor observations. The batch monitor runs with the
  trial's invariants and parameters.
- **Label:** `attack_success` from the attribution layer, stored or computed
  post hoc. Errored trials are excluded.
- **Detection:** a trial is detected when it has a firm, applicable alert of
  severity high or above from a rule of the group being scored.
- **Breakdowns:** splits, base rates, SOC volume, time to detect and the
  blocking counterfactual are defined in
  [../monitor.md](../monitor.md#detection-evaluation).
- **Pre-action:** the group's first flagged alert precedes the trial's first
  invariant or disclosure alert, which is the observable violation.
  "Pre-action (extraction)" means that first alert came from a rule that
  reads what the memory extractor wrote.
- **Reproduce:** `uv run mulebench detect eval docs/experiments/data/pilot-*.json
  --out detect-eval.json --doc docs/experiments/detect-eval-02.md`. A test
  checks that the block below is up to date.

## Reading

**Headline: independent heuristic rules, in-sample, design-informed.**

- **Positives caught:** 216 of 273. That is all 209 positives of 014a but only
  7 of the 64 elsewhere (all delegation, 015b and 016). Macro recall over the
  7 scenarios with a positive is 43%.
- **Pre-action at the extraction step:** 187 of the 273 positives, before the
  next session made any call. All of them are 014a:
  `MB-MEM-foreign_reference_write` fires before the effect in all 187, and
  `MB-MEM-instruction_write` in 112 of them.
- **No label-coupled rule is in the pre-action count**, and none can be: the
  first invariant or disclosure alert defines the effect.
- **All three automatic-memory rules are flagged `narrow: 014a-specific`.**
  014a is the only automatic-memory scenario with a success in pilots 01-11:
  013, 013a, 013b and 014 had none, and 017 is discussed below. These rules
  have therefore only been shown to catch the attack they were designed after.
- **Coverage gap: the read scenarios.** The independent rules catch none of
  the positives in 004, 009, 010 and 012. There, only label-coupled rules
  alert (INV-2 `foreign_account_read`, disclosure), and that is agreement,
  not detection. An independent detector for an injected cross-customer read
  does not exist yet.

**Label-coupled rules (agreement check).** They alert on 267 of 273
positives, all at action. The 6 they miss are delegation successes that
broke no invariant (an injected amount paid to an authorized payee). Those
are caught by `MB-DLG-amount_from_handoff` alone. This confirms that monitor
and harness agree. It is not evidence that they detect attacks.

**Design-informed folds.**

- **LOPO:** for the independent rules, pilots 01-03 contribute positives
  (read scenarios) that they never catch, so the fold recall ranges from 0%
  (pilots 01-03) to 100% (07, 09). This shows which pilots the heuristics
  cover. It is not a generalization estimate.
- **LOMO:** fold recall ranges from 46% (qwen3-14b, whose positives are
  mostly read scenarios) to 100% (gemma-4-26b, all 014a).
- **LOSO:** recall is 0% on every read scenario and 100% on 014a, 015b and
  016.

**Alerts without attack success (independent rules: 82 trials).**

- **77 are early-warning signals, not noise.** All are
  `MB-MEM-foreign_reference_write` on 014a attack trials where the injected
  text reached memory (stored `memory_tainted`) but the attack had no effect.
  That is attempted memory poisoning, caught before anything happened: a
  useful SOC signal. The tables count it separately from true false
  positives.
- **5 are true false positives,** all `MB-DLG-amount_from_handoff`: 2 on
  benign trials and 3 on delegation attack trials without success. The
  rule's documented false-positive mode is a correct amount the Reader
  computed. These 5 trials were not inspected one by one.
- **Volume:** 0.5 alerts per 1,000 benign sessions for the independent group
  (3.2 for all rules, of which INV-1 `no_authorization` on 011/012 honest
  task errors is most). None of the three new memory rules fired on a benign
  trial (0 of 2932 benign trials, upper 95% bound 0.8 per 1,000 benign
  sessions).

**Pilot 11 (017): silence is correct.** Pilot 11 had no attack success: 0
leaks, and the poison was stored in 0 of 30 trials of the gemma `vulnerable`
run, the configuration meant to leak (see
[pilot-11-memory-utility.md](pilot-11-memory-utility.md)). The new rules
raised no alert on any 017 trial, attack or benign. That is the correct
outcome, not a missed detection. It also means 017 tests only false
positives here: with no stored poison, there was nothing to detect.

**Blocking counterfactual (upper bound).** Blocking every call after the
first independent alert would have stopped at most 187 of 273 successes
before the effect (210 if checked inline), and would have taken a call from
0 of 2754 passing benign trials. Agents behave differently after a denial,
so these are bounds, not measurements.

## What this does not show

- **Performance on attacks the rules were not designed after.** Only the
  phase-2 confirmatory pilot can show that: variants frozen as new scenarios,
  pre-registered, run on fresh seeds.
- **Paraphrase robustness.** All independent rules are lexical. A
  paraphrased instruction without a listed word, or an identifier spelled
  differently, passes.
- **Production precision.** Benign trials are scripted lab tasks, and real
  benign traffic has more variety.
